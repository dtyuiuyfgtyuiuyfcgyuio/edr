# 监控文件哈希情报

FIM 已在同一文件句柄上验证身份并计算 SHA-256。本功能把现有 FIM 变化事件接入通用 IOC 检测，在文件被执行之前即可发现配置监控位置的已知恶意哈希，不新增文件读取或扫描器。

## 启用

配置已有开关和监控路径；以下路径与域为示例，需要换成实际配置。feed 沿用 `sha256` 指标格式。

```json
{
  "enable_fim_monitor": true,
  "fim_watch_files": ["C:\\EDR-Watch\\artifact.bin"],
  "threat_intel": {
    "enable": true,
    "feed_path": "rules/threat_intel.json",
    "min_score": 55,
    "reload_poll_seconds": 30
  }
}
```

仅配置的固定文件路径受监控，不递归扫描目录。首次完整快照继续建立静默基线；之后的新增或内容变化才触发检测。已存在的文件应使用其他已有扫描/执行遥测调查，此功能不增加启动扫描。

## 证据与规则

- `FILE_INTEGRITY`、`fim_action=added/modified`、`fim_baseline=true`、有效路径和完整 `fim_sha256` 是输入条件。
- 摘要只和 SHA-256 IOC 比较；不会用事件中的进程 `sha256` 字段代替文件摘要。
- 删除事件即使保留旧摘要也不参与匹配；缺失、畸形或不完整证据不评分。
- 文件证据单独评分，允许 PID 为零；不借用、添加或清理进程关联证据，也不推断文件由哪个进程创建。
- 共用的情报源热重载仍遵循既有事务规则：成功替换 feed 时统一清空旧 feed 的关联证据。
- 指标的生效、到期、撤销与操作员最低分阈值继续生效。默认哈希匹配为 85 分；阈值高于 85 时不输出文件评分。

正式规则 **EDR-520** 级别 high、动作 alert。它表示配置监控文件的当前 SHA-256 命中操作员情报，不表示文件已被执行，也不保证情报本身没有误报；T1204.002 映射仅提供恶意文件执行风险的调查关联。该功能不执行文件隔离、删除或进程处置，既有真实响应开关保持原默认值。

## 验证

```powershell
ctest --test-dir build -R 'threat_intel|fim_collector' --output-on-failure
```

IOC 专项和原生聚合测试新增四组回归：零 PID、文件与进程证据隔离、删除/缺失/畸形字段、生命周期与阈值。隔离用例还覆盖未来文件事件不能清理进程证据。

`edr_fim_collector_tests` 由 CTest 传入正式规则文件，创建并删除仅由本次测试拥有的良性临时文件，核验内容 first 的 SHA-256，经原生 FIM → EventBus → IOC → RuleEngine 触发 EDR-520，并检查删除事件不重复告警。测试不执行样本或安装驱动。手动直接运行时，可传 `rules/rules.json` 启用同一集成用例。

2026-10-18 验收：Release 构建通过；57 项 CTest 中 56 项通过、1 项权限跳过、0 失败。本地控制台 182 项、筛选发布副本 181 项通过；差异为发布副本排除了一个含静态 TLS 私钥样例的测试文件。生产规则共 513 条，最大编号 EDR-520，采集器和检测器数量不变。
